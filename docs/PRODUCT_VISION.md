# BuddyDog 产品愿景与设计原则

## 1. 产品定义
BuddyDog 不是“会动的宠物图片”，也不是披着宠物外壳的效率工具。它是一只有生命感的数字伙伴（Digital Companion）：在用户工作时安静陪伴，在合适的时候用符合狗狗身份的方式轻轻提醒，并随着长期使用逐步形成熟悉感。

## 2. 核心愿景
让用户在使用电脑工作时，感受到“它一直在旁边陪着我”，而不是“桌面上又多了一个通知软件”。

## 3. 产品原则
1. 陪伴优先于效率：效率是副产品，陪伴感是首要目标。
2. 少打扰：不抢占注意力，不频繁弹窗，不遮挡关键工作区域。
3. 行为有原因：每个动作都应能被用户理解为“它想这么做”，而非随机播放素材。
4. 它首先是一只狗：AI 是它的大脑，但表达、动作和关系都必须保持狗狗身份。
5. 一致性优先于动作数量：首版宁可动作少，也不能频繁变脸、变体型或性格漂移。
6. 长期耐看：避免过度卖萌、重复文案和高频反馈造成疲劳。
7. 隐私与本地优先：Phase 1 不要求上传个人工作内容，提醒配置和运行状态默认保存在本地。

## 4. 产品判断问题
开发任何功能前都要问：
- 真正的小狗会这样做吗？
- 这个动作是在陪伴，还是在打扰？
- 用户连续使用三个月后还会喜欢吗？
- 这个功能是否属于当前阶段？

## 5. Phase 1 边界
Phase 1 只解决三件事：
- 像：根据用户照片获得高一致性的狗狗形象。
- 活：在透明桌面窗口中自然待机、移动、休息和回应点击。
- 陪：以狗狗口吻定时提醒喝水、远眺和活动。

Phase 1 明确不包含：日历、DDL、邮件、聊天大模型、语音、云端账号体系、社区分享、自动生成完整动画模型的平台化能力。相关内容仅保留架构扩展位，不进入开发验收。
