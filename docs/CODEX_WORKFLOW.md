# 如何高效使用 Codex 开发 BuddyDog

## 1. 推荐使用方式
把本 Starter Pack 放到 Git 仓库根目录，尤其保留 AGENTS.md 和 docs/。Codex 适合直接在仓库中读取文件、修改代码、运行命令和测试。不要每次把整套 Word 文档重新粘贴进聊天；仓库文件应成为唯一事实来源。

建议组合：
- ChatGPT 项目对话：讨论产品、体验、优先级和文档变更。
- Codex 桌面应用或 IDE 扩展：在本地仓库中开发、运行、调试和审查改动。
- Codex cloud：仓库已连接 GitHub、环境可复现后，用于独立任务、并行实现或生成 PR。
- Codex CLI：适合你已经在终端工作、需要快速检查或自动化重复任务时使用。

## 2. 不要一次让 Codex 做完整项目
正确节奏：初始化 → 最小透明窗口 → 素材加载 → 状态机 → 互动 → 提醒 → 设置 → 打包 → 跨平台验收。
每个任务最好能在一次 diff 中审查，并包含清晰验收条件。

## 3. 每个任务的提示结构
1. 背景：引用相关规格文件。
2. 目标：只写一个可交付结果。
3. 范围：允许改哪些模块。
4. 禁止项：明确不要做什么。
5. 验收：可运行、可测试的条件。
6. 执行：要求先检查仓库，再给计划，再实施，再测试。

## 4. 模型/推理模式选择
界面名称可能随版本变化，原则如下：
- 快速/较低推理：小改文案、简单类型错误、查找代码位置。
- 中等/高推理：正常功能开发、跨文件重构、测试设计。
- 最高推理或更强模型：架构决策、复杂跨平台 Bug、安全审查、难以复现的问题。
不要所有任务都用最高档；先用正常档，把任务边界写清楚通常更有效。

## 5. 第一轮不要直接上传照片给 Codex“生成动画”
Codex 的主职责是工程实现。照片和动画素材应先通过图像/视频生成与人工整理流程产出透明帧序列，再作为 assets 放进仓库。Codex 负责验证格式、加载、播放和打包，不应被要求仅靠代码凭空制作高还原动画。

## 6. 建议的会话策略
- 一个 Codex 线程对应一个明确主题，例如“透明窗口基础”“状态机”“提醒系统”。
- 新任务开始时让 Codex 读取最新文档和当前 git 状态。
- 每个任务结束要求提供 diff 摘要、测试结果和风险。
- 重要里程碑打 Git tag；不要在一个巨大未提交工作区连续开发。
- 遇到跑偏，先更新规格或 AGENTS.md，再重新布置任务，不靠口头反复纠正。

## 7. 审查原则
Codex 完成不等于可以直接合并。至少检查：
- 功能是否符合 PRD，而非“看起来更丰富”。
- 是否引入不必要依赖或扩大范围。
- Windows/macOS 差异是否被考虑。
- 是否真的运行测试和构建。
- 透明窗口、鼠标事件和多显示器是否有手工验证说明。

## 8. 官方能力提示（截至 2026-07）
Codex 可在 ChatGPT、桌面应用、IDE 和 CLI 中使用；云端任务可在独立环境中运行并在完成后审查 diff 或创建 PR。具体界面和模型名称可能更新，应以 OpenAI 官方 Codex 文档为准。
